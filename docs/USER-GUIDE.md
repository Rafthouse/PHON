# PHON — Посібник: як має працювати плагін

> **Статус.** Документ описує задуманий і частково реалізований поведінку PHON.
> Кожен розділ позначено:
> **[Є в коді]** — працює в поточному коді;
> **[Задум]** — описано в прототипі, документації чи коментарях, але в коді ще не реалізовано;
> **[Прототип]** — поведінка лише в HTML-прототипі, не в плагіні.
>
> Поки DSP не реалізовано, плагін пропускає сигнал без змін за будь-яких налаштувань.

---

## 1. Що таке PHON

PHON (Perceptual Harmonic Inflator) — аудіоплагін VST3 (і згодом AU), який додає гармоніки до сигналу. Ідея: гармоніки зважуються за кривою рівної гучності ISO 226, щоб звучання було «наповненим» без відчутного гучного писку в тих діапазонах, де вухо чутливіше.

**Формат і збирання:** JUCE 7.0.12, CMake, C++17. Цільові платформи — Windows, macOS, Linux (див. `README.md`).

---

## 2. Параметри

Усі параметри зберігаються в `AudioProcessorValueTreeState` під зазначеними ID. Не змінюйте ID без міграції пресетів — вони йдуть в автоматизацію й збережені стани.

| ID | Назва в UI | Тип | Діапазон | За замовчуванням | Призначення |
|---|---|---|---|---|---|
| `input` | INPUT | float | −12 … +12 dB, крок 0.1 | 0 dB | Вхідний трім перед генератором гармонік |
| `amount` | AMOUNT | float | 0 … 100, крок 0.5 | 35 | Загальна інтенсивність генерації гармонік |
| `phon` | PHON | float | 0 … 100, крок 0.5 | 50 | Сила кореляції гармонік із кривою ISO 226 (0 = звичайний інфлятор) |
| `density` | DENSITY | float | 0 … 100, крок 0.5 | 20 | Адаптивне ущільнення, зниження crest factor |
| `mix` | MIX | float | 0 … 100, крок 0.5 | 100 | Dry/Wet-баланс |
| `output` | OUTPUT | float | −12 … +12 dB, крок 0.1 | 0 dB | Вихідний трім після обмежувача |
| `character` | CHARACTER | вибір | CLEAN · TUBE · IRON · DENSE | CLEAN | Характер гармонічного ядра |
| `oversampling` | OVERSAMPLING | вибір | OFF · 2× · 4× · 8× | OFF | Внутрішня передискретизація |
| `safePeak` | SAFE PEAK | перемикач | ON / OFF | ON | Захист від піків на виході |
| `bypass` | (PROCESS) | перемикач | ON / OFF | OFF | Байпас усього процесора |

**Важливо про PROCESS.** У коді зберігається `bypass`, а в інтерфейсі показується `PROCESS`. Відображення має бути інвертованим: `PROCESS = ON` ⇔ `bypass = OFF`. Прототип показує ON за замовчуванням, що відповідає `bypass = false`. **[Задум]** — інверсію ще потрібно реалізувати в UI.

**Розбіжність демо-значень.** У прототипі стартові значення AMOUNT 38, PHON 64, DENSITY 27 — це демонстраційний стан, а не значення за замовчуванням плагіна. Для плагіна діють значення з таблиці.

## 3. Сигнальний ланцюг

```
Вхід → Input trim → Harmonizer → Density Shaper → Safe Peak → Output trim → Dry/Wet → Вихід
                         │
                    вага ISO 226 (PHON)
```

Порядок задано в `Source/DSP/PhProcessor.h` і `docs/ARCHITECTURE.md`.

**[Є в коді]** Сам ланцюг — лише каркас: `PhProcessor::processBlock` читає параметри, але жоден модуль не викликається. Якщо `bypass` увімкнено, блок повертається без обробки. Інакше сигнал проходить без змін.

**Спектральні точки PRE і POST [Є в коді]:**
- PRE знімається *до* ланцюга, POST — *після* нього.
- Зараз, оскільки ланцюг пустий, PRE і POST однакові.

### 3.1 Input trim [Задум]
Додає або віднімає до ±12 dB перед генератором гармонік. Визначає, наскільки сильний сигнал потрапляє в модулі.

### 3.2 Harmonizer [Задум]
Шість смуг, кожна генерує гармоніки з власною вагою.
- **CHARACTER** визначає, які гармоніки беруться:
  - **CLEAN** — нейтральне переназначення гармонік.
  - **TUBE** — переважно парні гармоніки; м'яке, округле звучання.
  - **IRON** — переважно непарні гармоніки; жорсткіший трансформаторний тон.
  - **DENSE** — максимальна «наповненість», найбільша вага.
- **AMOUNT** масштабує загальну кількість гармонік.
- **PHON** визначає, наскільки вага гармонік корелює з ISO 226. При 0 вага не залежить від кривої.

*Примітка:* у прототипі вага характерів схематично така: CLEAN 0.72, TUBE 0.86, IRON 1.0, DENSE 1.22. Це ілюстрація, а не специфікація DSP.

### 3.3 OVERSAMPLING [Задум]
- **OFF** — нативна частота дискретизації.
- **2× / 4× / 8×** — Harmonizer працює на підвищеній частоті, щоб зменшити алізинг від гармонік. Чим вище коефіцієнт, тим якісніше й тим більше навантаження на CPU.

*Зараз не реалізовано:* параметр зберігається, але не впливає на звук.

### 3.4 Density Shaper [Задум]
Адаптивне зменшення crest factor: знижує піки, зберігаючи сприйману гучність. DENSITY визначає силу ефекту. При 0 — без змін (цей інваріант закладено в тест `DensityShaper`).

### 3.5 Safe Peak [Задум]
Lookahead-обмежувач останнього каскаду. За коментарями в коді: lookahead близько 2 мс, поріг близько −0.3 dBTP, відновлення плавне, без клацань. Вимкнення SAFE PEAK прибирає обмеження.

### 3.6 Output trim [Задум]
Додає або віднімає до ±12 dB після обмежувача.

### 3.7 Dry/Wet — MIX [Задум]
Змішує необроблений (dry) і оброблений (wet) сигнали за MIX:
- 100 — лише оброблений сигнал;
- 0 — лише dry.

Для коректного змішування dry-копія має зберігати той самий рівень і фазу, тобто мати ту саму затримку, що й оброблений сигнал. Якщо lookahead обмежувача вноситиме затримку, її треба компенсувати й повідомляти хосту.

## 4. Інтерфейс

### 4.1 Шапка
- **Бренд:** PHON, підзаголовок «Perceptual Harmonic Inflator», авторство.
- **OVERSAMPLING:** select зі значеннями OFF / 2× / 4× / 8×. Підпис над полем, стрілка праворуч.
- **PROCESS:** switch ON/OFF з підписом над ним. Вимкнений стан — приглушений, увімкнений — бурштиновий.

**[Прототип]** OVERSAMPLING і PROCESS розташовані в одному рядку, підписи на одній лінії, контроли по 32 px.

### 4.2 Центральна зона
- **Графік** — основний елемент. Зараз у нативному плагіні — дисплей спектра, у прототипі — ілюстрація ISO 226.
- **INPUT** і **OUTPUT** — ліворуч і праворуч від графіка. Кожен блок: назва, ручка, значення в dB, вертикальний індикатор рівня.
- **PRE / POST** — перемикачі в заголовку графіка. Вони лише показують або приховують відповідні криві (див. розділ 5).

### 4.3 Нижній ряд
- **CHARACTER** — select, ліворуч.
- **SAFE PEAK** — switch з текстом ON/OFF.
- **AMOUNT, PHON, DENSITY, MIX** — ручки. PHON — найбільша.

### 4.4 Footer
Ліворуч — службовий текст, праворуч — авторство-оформлення; посередині — коротка довідка при наведенні на контрол («Наведіть курсор на контрол»). Довідка не повинна накладатися на службові написи.

## 5. Графік і спектри

### 5.1 Нативний дисплей [Є в коді]
- Два спектри: **PRE** (сірувато-світлий, напівпрозорий) і **POST** (бурштиновий, із заливкою).
- Шкала частот логарифмічна, 20 Гц – 20 кГц. Шкала рівня −90 … 0 дБ.
- FFT 2048 точок, вікно Ханна. Оновлення приблизно 30 разів на секунду.
- Перемикачі PRE і POST лише вмикають і вимикають криві. Жодного іншого ефекту на обробку вони не мають.
- **Без вхідного сигналу спектр лишається на рівні −90 дБ.** Це очікувана поведінка, а не дефект: порожній графік означає відсутність звуку.

### 5.2 Прототип [Прототип]
- Світла крива — ілюстративна «вхідна» крива ISO 226.
- Бурштинова крива — ілюстративна «вихідна» з урахуванням ваг гармонік.
- Вертикальні смуги — ваги шести гармонічних смуг, схематичні.
- **Ці дані не відповідають фактичним розрахункам**, бо DSP не реалізовано.

### 5.3 Напис «ISO 226» [Задум]
У коді ISO 226 не реалізовано. Напис у заголовку графіка відображає задум. Його можна вважати правдивим лише після реалізації відповідної ваги.

## 6. Індикатори рівня

**[Задум]** INPUT і OUTPUT мають вертикальні індикатори (RMS, пік, PHON-оцінка). Шкала, часові характеристики й прив'язка до джерела даних — ще не визначені.

**[Прототип]** Заливка фіксована на 35% і не відображає сигнал.

**Правило:** індикатори не показують вигаданих даних. Якщо джерела немає, індикатор стоїть на нулі.

---

## 7. Ручки: керування

**[Прототип]** — поведінка для всіх ручок:
- **Перетягування вертикально** — основний спосіб. Перетягування вправо також змінює значення.
- **Shift + перетягування** — точне регулювання (кратність 0.18).
- **Колесо миші** — крок 1/100 діапазону, Shift — 1/500.
- **Подвійний клік** — скидання до значення за замовчуванням.
- **Клавіатура** (коли ручка у фокусі): стрілки — крок, Home — мінімум, End — максимум.

**Вимога до нативної версії:** ті самі способи взаємодії, без зміни чутливості, без інерції й без анімації, яка відставала б від значення.

**Малювання ручки:** освітлення, корпус і фаска нерухомі. Обертається лише покажчик, а дуга змінює довжину пропорційно значенню. Кут: від −135° (мінімум) до +135° (максимум).

---

## 8. Вибори (select)

- **OVERSAMPLING** і **CHARACTER** відкривають список вниз.
- Список не виходить за межі вікна.
- Вибраний пункт виділено.
- Значення в полі завжди відповідає параметру.

---

## 9. Збереження, автоматизація, хост

- **Стан** зберігається через `getStateInformation` як XML з усіма параметрами. Відновлення — через `setStateInformation`.
- **Автоматизація:** кожен параметр з ID з таблиці доступний хосту. Зміна з хоста має оновлювати ручку, select і switch.
- **Затримка:** поки немає lookahead-обмежувача, плагін не повідомляє хосту про затримку. Після реалізації Safe Peak затримку треба повідомити хосту, інакше виникне зсув у доріжці.

## 11. Як перевірити поведінку

1. **Збирання та тести:** `cmake -B build -DBUILD_TESTS=ON`, `cmake --build build --target PHON_Tests`, запуск `PHON_Tests`. Тести на DSP-заглушки перевіряють лише те, що вони не падають, і не є доказом роботи.
2. **Спектр:** подати синусоїду 1 кГц — пік має бути в бінах біля 1 кГц (тест `TestSpectrumAnalyzer`).
3. **Прототип:** відкрити `Design/Prototypes/index.html` через локальний сервер і перевірити перемикачі, ручки, select, switch.
4. **Нативний плагін:** після реалізації DSP — перевірити в DAW: silence passthrough, тон → FFT гармонік, відповідність параметрів, збереження та відновлення стану.
